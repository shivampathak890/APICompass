# APICompass Evidence Adjudication & Verification Guide

This guide documents the strengthened evidence adjudication and verification architecture of APICompass, including strict quotation verification, source provenance rules, mock evidence quarantine, defense against LLM suggestion elevation, and explicit examples of accepted vs. rejected findings.

---

## 1. Core Adjudication Invariants

1. **Deterministic Verification Guarantee**:
   Every reported `VerifiedIssue` must be substantiated by either:
   - An exact verbatim (or whitespace-normalized) quotation matching the official documentation retrieved from approved domains (`docs.stripe.com`, `stripe.com`).
   - A verified structured contract definition extracted from authentic documentation.
2. **Quote vs. Paraphrase Distinction**:
   - Quotes matching verbatim are labeled `quote_kind: "exact_quotation"`.
   - Text with altered phrasing, summary wording, or word modifications is detected and classified as `quote_kind: "paraphrase"`. Paraphrases are **strictly rejected** from establishing a verified contract violation.
3. **Synthetic Mock Evidence Quarantine**:
   - Any documentation originating from offline mock fixtures (`provider == "tinyfish_mock"`, `is_mock == True`, or `source_trust == "mock_fixture"`) can **never** substantiate a verified finding or official quotation.
   - Mock evidence causes candidate assessments to abstain with `status: "unresolved"` and `abstention_reason: "MOCK_EVIDENCE_ONLY"`.
4. **Endpoint & Resource Relevance Enforcement**:
   - Evidence must directly correspond to the target API resource and method. Documentation for a disjoint resource (e.g., retrieving Customer documentation to evaluate a `stripe.Charge.create` call) is flagged as irrelevant and **rejected**.
5. **Conflicting Documentation Handling**:
   - If multiple retrieved documentation records present conflicting parameter constraints or deprecation states, APICompass preserves uncertainty, marks the candidate as `unresolved` with `abstention_reason: "CONFLICTING_DOCUMENTATION"`, and abstains.
6. **Strict Wall Against LLM Suggestion Elevation**:
   - AI suggestions generated by heuristic or probabilistic LLM reasoning are quarantined in `report.ai_suggestions` with badge `label: "Unverified suggestion"` and `verification_status: "unverified_suggestion"`.
   - An LLM suggestion can **never** be promoted into `verified_issues`.
7. **Explicit Result States**:
   Every candidate, issue, and overall report displays one of four explicit states:
   - `Verified`: Evidence-supported contract violation confirmed.
   - `Unverified suggestion`: Probabilistic hypothesis from AI reasoning.
   - `Unable to verify`: Evidence missing, ambiguous, incomplete, or quarantined.
   - `No issue detected within the checks performed`: Verified clean within the analyzed scope.
8. **Clean Scan Non-Implication**:
   - A clean scan certifies **only** that no violations were detected for supported calls against retrieved documentation.
   - It carries an explicit disclaimer that it does **not** certify that the entire program is correct, complete, or bug-free.

## 2. Examples of Accepted Findings

### Example 1: Deprecated Parameter Violation (Exact Quotation)

- **Source Code Under Analysis**:
  ```python
  import stripe
  stripe.api_key = "sk_test_123"

  charge = stripe.Charge.create(
      amount=2000,
      currency="usd",
      source="tok_12345",
  )
  ```
- **Retrieved Evidence**:
  - URL: `https://docs.stripe.com/api/charges/create`
  - Trust: `live_official_source` (`is_mock: false`)
  - Excerpt:
    > "You can use the Charges API to accept payments using Stripe. The 'source' parameter is considered legacy; PaymentIntents should be used for modern payment methods. Required parameters: amount (positive integer), currency (three-letter ISO code)."
- **Adjudication Outcome**:
  - `verification_status`: `"verified"`
  - `violation_type`: `"legacy_deprecated_parameter"`
  - `claim_checked`: `"Deprecated parameter 'source' in stripe.Charge.create"`
  - `quote_kind`: `"exact_quotation"`
  - `match_method`: `"exact"`
  - `verified_quote`: `"The 'source' parameter is considered legacy; PaymentIntents should be used for modern payment methods."`
  - `supporting_excerpt`: `"You can use the Charges API to accept payments using Stripe. The 'source' parameter is considered legacy; PaymentIntents should be used for modern payment methods. Required parameters: amount (positive integer), currency (three-letter ISO code)."`
  - `evidence_rationale`: `"Verified against official documentation at https://docs.stripe.com/api/charges/create. Exact quotation matches source excerpt via exact matching."`
  - **Result**: **ACCEPTED** into `verified_issues`.

## 3. Examples of Rejected Findings

### Example 2: Paraphrased or Altered Quotation

- **Claim**: The caller claims that `source` is invalid on `stripe.Charge.create`.
- **Claimed Quotation**:
  > `"The 'source' parameter is deprecated and PaymentIntents must be used for payment methods."`
- **Retrieved Source Text**:
  > `"The 'source' parameter is considered legacy; PaymentIntents should be used for modern payment methods."`
- **Adjudication Outcome**:
  - `is_verified`: `false`
  - `quote_kind`: `"paraphrase"`
  - `error_message`: `"Quotation appears to be a paraphrase rather than an exact quotation. Exact verbatim match is required for verified issues."`
  - **Result**: **REJECTED**. Paraphrases are never certified as official quotations or verified findings.

---

### Example 3: Irrelevant Endpoint / Resource Documentation

- **Source Code Under Analysis**:
  ```python
  stripe.Charge.create(amount=1000, source="tok_visa")
  ```
- **Evidence Supplied**:
  - URL: `https://docs.stripe.com/api/customers/create`
  - Title: `Create a customer | Stripe API Reference`
  - Excerpt: `"Creates a new customer object. Optional parameters: source (legacy payment source token)."`
- **Adjudication Outcome**:
  - Relevance Check: `is_evidence_relevant()` evaluates candidate resource (`charge`) against evidence canonical URL (`/customers/create`).
  - Relevance Error: `"Evidence from https://docs.stripe.com/api/customers/create relates to 'customer' resource, which is irrelevant to candidate operation 'stripe.Charge.create'."`
  - **Result**: **REJECTED**. Finding is discarded before quote evaluation.

---

### Example 4: Conflicting Documentation Across Retrieved Sources

- **Source Code Under Analysis**:
  ```python
  stripe.Charge.create(amount=1000, currency="usd", source="tok_visa")
  ```
- **Retrieved Sources**:
  - Source A: Marks parameter `source` as deprecated: `"The 'source' parameter is considered legacy; PaymentIntents should be used."`
  - Source B: Marks parameter `source` as required: `"Required parameters: amount, currency, source."`
- **Adjudication Outcome**:
  - `match_record.is_ambiguous`: `true`
  - `match_record.match_rationale`: `"Conflicting documentation detected across retrieved sources for 'stripe.Charge.create'."`
  - Candidate Assessment: `status: "unresolved"`, `abstention_reason: "CONFLICTING_DOCUMENTATION"`.
  - Overall Verdict: `verdict: "unable_to_verify"`.
  - **Result**: **ABSTENTION**. Uncertainty is preserved; zero unproven violations are reported.

---

### Example 5: Synthetic Mock Evidence Quarantine

- **Source Code Under Analysis**:
  ```python
  stripe.Charge.create(amount=1000, currency="usd", source="tok_visa")
  ```
- **Evidence Supplied**:
  - URL: `https://docs.stripe.com/api/charges/create`
  - Source Trust: `mock_fixture` (`provider: "tinyfish_mock"`, `is_mock: true`)
  - Excerpt contains exact text: `"The 'source' parameter is considered legacy; PaymentIntents should be used..."`
- **Adjudication Outcome**:
  - `QuoteVerifier.verify_official_quote`: Returns `is_verified: false, is_mock: true, error_message: "Synthetic mock text cannot be presented as an official quotation."`
  - Adjudicator Quarantine: Candidate marked `unresolved` with `abstention_reason: "MOCK_EVIDENCE_ONLY"`.
  - Report: `verdict: "unable_to_verify"`, `result_state: "unable_to_verify"`, `verified_issues: []`.
  - **Result**: **QUARANTINED**. Mock fixtures can never produce production verified issues.

---

### Example 6: Unsupported AI Suggestion Defense

- **AI Reasoner Hypothesis**:
  - LLM outputs an `AISuggestion` alleging: `"Critical API Vulnerability Allegation: stripe.Charge.create requires an idempotency key."`
  - `confidence: "high"`.
- **Adjudication Outcome**:
  - Suggestion remains in `report.ai_suggestions` with badge `label: "Unverified suggestion"` and `verification_status: "unverified_suggestion"`.
  - Deterministic Adjudication verifies code against retrieved contract. No official documentation establishes idempotency keys as mandatory.
  - `report.verified_issues` contains **zero** issues from the suggestion.
  - **Result**: **QUARANTINED AS UNVERIFIED SUGGESTION**. LLMs cannot promote unsupported suggestions into verified issues.

---

### Example 7: Clean Scan Scope Limitation

- **Source Code Under Analysis**:
  ```python
  stripe.PaymentIntent.create(amount=2000, currency="usd")
  ```
- **Retrieved Evidence**:
  - Authentic live documentation for `stripe.PaymentIntent.create`. All required parameters (`amount`, `currency`) are provided, and no deprecated parameters are used.
- **Adjudication Outcome**:
  - `verdict`: `"clean"`
  - `result_state`: `"no_issue_detected"`
  - `summary`: `"No issue detected within the checks performed across 1 analyzed candidate(s). This does not certify or imply that the entire program is correct, complete, or bug-free."`
  - `limitations_and_caveats`: Includes `"SCOPE_LIMITATION: A 'No issue detected within the checks performed' result only covers supported API calls verified against retrieved documentation contracts. It does not certify general program correctness, runtime behavior, or unanalyzed dependencies."`
  - **Result**: **NO ISSUE DETECTED WITHIN THE CHECKS PERFORMED** with clear non-implication caveat.
